账号 · us-east-2 · EKS aigw-dev · 入口 aigw.example.com · 五类模型全部走 Bedrock，每模型双通路（use2 主 / use1 备）· 代码 ~/Documents/dev/envoy-aigw

一次推理请求的完整路径

  • • 客户端解析 aigw.example.com（Cloudflare → Route 53 委派）→ ALB 公网 IP，TLS 1.3 在 ALB 终止（ACM 通配符证书）
  • • ALB 按 Host 转发到 Envoy Pod :10080（ip target，无 NodePort）；SSE 流式不缓冲，空闲超时 600s
  • • Envoy：API Key 校验并注入 x-aigw-client → 全局限流（Redis 计数）→ extproc 解析 model → 选 cluster（use2 90 / use1 10）→ 协议转换 → SigV4
  • • 主通路经 VPC 终端节点私网到 Bedrock us-east-2；备通路经 NAT 公网到 us-east-1；失败/429 重试落另一通路
  • • 响应流回时 extproc 统计 token 写入动态元数据 → 限流扣费 + gen_ai_* 指标（按模型 / 通路 / 客户端）

身份与凭证边界

  • • 用户 → 网关：静态 API Key（Secrets Manager 为源，集群 Secret 为副本，Envoy 秒级生效）
  • • 网关 → Bedrock：EKS Pod Identity 短期凭证，角色按 Bedrock 动作收窄；集群内没有任何长期 AK/SK
  • • 运维 → Prometheus / Dashboard：ALB 的 Cognito 登录（用户池 aigw-dev-ops）；Grafana 自带登录
  • • ALB 控制器、EBS CSI、Dashboard 各自独立的 Pod Identity 角色，最小权限
  • • 边缘：Shield Standard（三四层 DDoS）；未挂 WAF、未订阅 Shield Advanced

容量与可用性设定（50 用户档）

  • • 2 × m7i.large 跨 2 AZ；Envoy 2 副本 + PDB，设计容量约 500 路并发流
  • • 请求体缓冲 50Mi、请求超时 900s、熔断阈值 8192、滚动发布 drain 300s 与 ALB 注销延迟对齐
  • • 每模型双通路 + 被动健康检查 + 重试：错误触发的秒级切换；权重是后续 Scorer 的调节旋钮
  • • 单 NAT、集群内单副本 Redis、无 Alertmanager 是 dev 取舍；prod 档改为每 AZ NAT、ElastiCache、3 节点组
  • • 监控：Prometheus 15d / 20Gi，7 个抓取目标；Grafana 官方 GenAI 看板；自研 Dashboard 聚合运维视图
