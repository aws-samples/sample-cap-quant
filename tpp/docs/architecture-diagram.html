TPP — Token Proxy Platform

Unified LLM channel proxy: USD quota · Metrics · Trace · Intelligent weight scheduling · Unified portal Dashboard — EKS tpp-dev · us-west-2

Core Path · Dual-Mode Access

  • • LiteLLM Proxy ×2, OpenAI-compatible + Anthropic-native dual protocol (:4000, local tunnel :14000)
  • • Per-user USD quota, deducted in real time from actual spend, auto-resets every 1d
  • • 9 channels = 4 Claude model groups × 2 Bedrock regions + gpt-5.6-terra (Bedrock Mantle, for Codex); IRSA, zero static keys
  • • Clients hit Bedrock directly by default; switch to TPP on demand via claude-tpp / codex --profile tpp. A TPP outage never affects the troubleshooting assistant

Observability · Unified Portal

  • • TPP Dashboard (:3020): user quotas editable with write-back, channel spend / health / weights, TTFT / TPOT / E2E / TPS percentiles, links to the other four UIs
  • • Prometheus 15d: TTFT / TPOT / E2E / Error (channel × model); Grafana TPP Overview + 4 alerts
  • • Langfuse v4 traces (langfuse_otel, OTLP) → ClickHouse + S3; accounting data lives in RDS
  • • Dashboard / Prometheus have no auth of their own; security relies on no exposed Ingress and tunnel-only access

Scorer Scheduling · Security & Resilience

  • • Every 60s: quality_score = 0.35 × latency_score + 0.65 × error_score; EWMA α=0.3, γ=2 amplifies score gaps → weight, state kept in Redis
  • • 5% exploration floor prevents lockout; breaker zeroes a channel when severe errors dominate; 2pp hysteresis on write-back; weights freeze when dependencies are unavailable
  • • RDS managed master password, 7d rotation: ESO polls every 5m → Reloader rolling-restarts LiteLLM / Langfuse, no manual intervention
  • • Local tunnels run as launchd daemons, each with a health-probe watchdog (rebuilt after 3 failed 15s probes)
